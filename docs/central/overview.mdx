Odigos Central is a centralized management layer for multi-environment observability. Instead of configuring instrumentation, [sampling rules](/enterprise/pipeline/sampling/rules/overview), and destinations separately in each place, Odigos Central provides a **single pane of glass** to manage:

- [Remote Kubernetes clusters](/central/adding-connections/remote-clusters)
- [VM Agent](/central/adding-connections/vmagent) hosts
- [Cloud Connectors](/cloud-connectors/overview) for cloud accounts (AWS, GCP, and more)

## Why Use Odigos Central?

- **Unified Management** - Configure instrumentation, sampling rules, and observability pipelines across clusters, VMs, and cloud accounts from a single UI
- **Reduced Operational Overhead** - No need to SSH or `kubectl` into each environment separately
- **Centralized Access Control** - Manage user authentication and authorization with support for SSO providers like Okta
- **Consistent Configuration** - Apply the same sampling and instrumentation rules uniformly across environments
- **Audit and Compliance** - Single point of control for observability configuration changes

After [installation](/central/installation), use [port-forward](/central/ui) for local access, or expose Central with ingress for production ([Authentication](/central/authentication#production-ingress-configuration)).
